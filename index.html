도전과제 1. Wav2Vec2 + LoRA 어린이 음성 인식 모델 개발

배경

난독증 아동의 발음 훈련을 위해서는 정확한 음성 인식이 필수적이지만, 기존 한국어 음성 인식 모델은 주로 성인 음성으로 학습되어 어린이 음성에 대한 인식률이 낮았습니다. 특히 난독증 아동은 발음이 불분명한 경우가 많아 일반 모델로는 제대로 인식하기 어려웠습니다.

초기 테스트에서 베이스 Wav2Vec2 모델의 PER(음소 오류율)이 36.67%로, 실제 교육에 활용하기에는 부족한 수준이었습니다. 또한 3억 개 파라미터를 전체 파인튜닝하려면 GPU 메모리와 학습 시간이 과도하게 소요되는 문제가 있었습니다.

과정

1) Wav2Vec2 기반 모델 선정

  • Wav2Vec2는 43.6만 시간의 오디오로 사전학습된 강력한 음성 인식 모델
  • Self-Supervised Learning으로 라벨 없이 음성의 패턴을 학습하여 일반화 성능 우수
  • 한국어 어린이 음성 데이터로 파인튜닝하여 도메인 특화 모델 구축

2) LoRA(Low-Rank Adaptation) 적용

  • 전체 3억 파라미터 중 단 1.5%(약 450만 파라미터)만 학습
  • 기존 가중치는 고정하고, 저차원 행렬(Low-Rank Matrix)만 추가하여 파인튜닝
  • GPU 메모리 사용량 70% 감소, 학습 시간 60% 단축
  • 성능은 전체 파인튜닝과 거의 동일하면서도 효율적

3) Curriculum Learning 전략 설계

  • 1단계 (30시간): 발음이 명확한 어린이 음성으로 기본 학습
  • 2단계 (90시간): 중간 난이도 발음 추가 학습 (약간 불분명한 발음 포함)
  • 3단계 (148시간): 난독증 아동 음성 등 어려운 케이스까지 학습
  • 쉬운 데이터부터 점진적으로 난이도를 높여 학습 안정성 및 수렴 속도 향상

4) 데이터 전처리 및 증강

  • AI Hub 어린이 음성 데이터셋 정제: 노이즈 제거, 음량 정규화
  • Data Augmentation: 속도 변화(0.9x ~ 1.1x), 피치 변화, 배경 소음 추가
  • 음소 단위 레이블링으로 발음 오류 세밀하게 탐지

결과

  • PER(음소 오류율) 60.3% 개선 (36.67% → 14.55%)
  • 베이스 모델 대비 2.5배 정확도 향상으로 실용 수준 달성
  • LoRA 적용으로 전체 파라미터의 1.5%만 학습하며 GPU 메모리 70% 절감
  • Curriculum Learning으로 학습 시간 40% 단축 및 안정적 수렴
  • 난독증 아동 발음도 85% 이상 정확도로 인식

배운 점: Parameter-Efficient Fine-Tuning(PEFT) 기법인 LoRA의 효과를 체감했습니다. 전체 파라미터의 1.5%만 학습해도 전체 파인튜닝과 거의 동일한 성능을 낼 수 있다는 것이 놀라웠고, 제한된 자원으로도 고품질 AI 모델을 개발할 수 있다는 가능성을 확인했습니다. 또한 Curriculum Learning 전략을 통해 학습 안정성과 수렴 속도를 크게 개선할 수 있었고, 데이터 순서와 난이도 조절이 모델 성능에 미치는 영향을 깊이 이해하게 되었습니다.

도전과제 2. BKT 알고리즘 기반 개인별 숙련도 추적 시스템 구현

배경

Reading Buddy는 난독증 아동의 발음 학습을 돕는 시스템으로, 각 아동마다 학습 속도와 음소별 숙련도가 크게 다릅니다. 단순히 정답/오답만으로는 아동의 실제 이해도와 학습 진행 상태를 정확히 파악하기 어려웠고, 획일적인 학습 경로는 학습 효율성을 떨어뜨렸습니다.

따라서 각 아동의 음소별 숙련도를 확률적으로 추정하고, 취약한 음소를 자동으로 파악하여 개인 맞춤형 학습 콘텐츠를 제공할 수 있는 Bayesian Knowledge Tracing(BKT) 알고리즘 기반 시스템 구현이 필요했습니다.

과정

1) BKT 알고리즘 이론 학습 및 적용

  • BKT의 4가지 핵심 파라미터 이해: P(L₀) 초기 지식, P(T) 학습 전이, P(S) 실수 확률, P(G) 추측 정답 확률
  • 베이지안 추론을 통해 학생의 지식 상태(mastered/not mastered)를 확률적으로 추정
  • 각 음소를 개별 지식 요소(Knowledge Component)로 정의하여 음소별 숙련도 추적

2) 통계학 전공 지식을 활용한 팀 협업

  • 통계학과 배경을 살려 베이지안 추론과 확률 모델 원리를 자바 백엔드 팀원들에게 설명
  • BKT 수식과 파라미터 업데이트 로직을 수학적으로 정리하여 공유
  • 학습 데이터를 기반으로 파라미터 초기값 설정 및 EM 알고리즘을 통한 최적화 방법 제시
  • Java로 구현할 BKT 엔진의 로직 설계 및 검증 참여

3) 실시간 숙련도 추적 시스템 구축

  • 아동이 발음 연습을 할 때마다 실시간으로 BKT 파라미터 업데이트
  • KC별 mastery probability 계산하여 DB에 저장
  • 숙련도가 낮은 KC 관련 문제를 우선적으로 제시하는 adaptive learning path 구현

결과

  • 각 아동의 KC(지식단위)별 숙련도를 0~1 확률값으로 실시간 추적
  • 취약 KC를 자동으로 파악하여 맞춤형 학습 콘텐츠 추천
  • 학습자별 adaptive learning path 제공으로 학습 효율성 향상

배운 점: BKT 알고리즘의 수학적 원리를 이해하고 이를 팀원들에게 명확히 전달함으로써, 복잡한 확률 모델을 실제 서비스에 성공적으로 적용할 수 있었습니다. 또한 개인 맞춤형 학습이라는 교육적 가치를 기술로 구현해내는 과정에서 큰 보람을 느꼈습니다.

전체 회고

Wav2Vec2 + LoRA 조합으로 제한된 자원에서도 고성능 모델을 개발할 수 있었고, Curriculum Learning 전략을 통해 학습 안정성과 수렴 속도를 크게 개선했습니다. 또한 BKT 알고리즘을 통한 개인 맞춤형 숙련도 추적 시스템을 구현하며, 통계학 전공 지식을 실무에 활용하여 팀에 기여할 수 있었습니다.

이 프로젝트를 통해 기술이 사회 문제를 해결하는 도구가 될 수 있다는 확신을 얻었고, 앞으로도 의미 있는 가치를 창출하는 개발자가 되고 싶다는 목표가 생겼습니다.

도전과제 1. 제한된 리소스 환경에서 60TB 데이터 처리

배경

삼성전자로부터 제공받은 5G RAN 네트워크 데이터는 압축 해제 시 60TB에 달하는 대용량이었습니다. 하지만 주어진 개발 환경은 16GB RAM과 1TB 스토리지로 제한되어 있었고, 일반적인 Pandas 기반 전처리 방식으로는 데이터를 메모리에 로드하는 것조차 불가능했습니다.

초기 시도 시 단일 Cell 데이터(약 80GB)를 불러오는 과정에서 메모리 부족(Out of Memory) 에러가 발생했고, 이대로는 프로젝트 진행 자체가 불가능한 상황이었습니다. 주어진 환경에서 60TB 데이터를 효율적으로 전처리하고 학습에 활용할 방법을 찾아야 했습니다.

과정

1) DuckDB 도입: 메모리 효율적 데이터 처리

  • Pandas 대신 DuckDB 사용: SQL 기반 컬럼 선택 및 필터링으로 필요한 데이터만 메모리에 로드
  • Lazy Evaluation 방식으로 쿼리 실행 시점을 늦춰 메모리 사용 최적화
  • 병렬 처리 기능을 활용해 CPU 코어를 효율적으로 사용
  • 결과: 80GB 데이터를 처리하는 데 필요한 메모리 80GB → 16GB로 80% 감소

2) Parquet 포맷 변환: 저장 공간 최적화

  • CSV 포맷(압축 해제 시 60TB) → Parquet 포맷(8.4TB)으로 변환
  • 컬럼별 압축(Columnar Storage) 및 타입 최적화로 저장 공간 86% 감소
  • Parquet는 DuckDB와 호환성이 뛰어나 읽기 속도도 CSV 대비 5배 이상 향상

3) 청크 단위 배치 처리

  • 전체 데이터를 Cell 단위로 분할하여 순차 처리
  • 각 Cell 데이터를 처리한 후 결과만 저장하고 메모리 해제
  • 배치 처리 중 중간 결과를 임시 저장하여 재시작 시 이어서 처리 가능

결과

  • DuckDB 도입으로 메모리 사용량 80% 감소 (80GB → 16GB)
  • Parquet 포맷 활용으로 저장 공간 86% 감소 (60TB → 8.4TB)
  • 데이터 로딩 속도 5배 이상 향상 (CSV 대비)
  • 제한된 리소스 환경에서도 전체 60TB 데이터를 성공적으로 전처리 및 학습 가능

배운 점: 리소스 제약이 오히려 최적화 기술을 배우는 계기가 되었습니다. Pandas 같은 익숙한 도구에만 의존하지 않고, DuckDB라는 새로운 도구를 빠르게 학습하고 적용하면서 문제 해결 능력을 키울 수 있었습니다. 또한 데이터 포맷 선택(CSV → Parquet)이 성능에 미치는 영향을 체감하며, 적절한 도구와 포맷 선택의 중요성을 깨달았습니다.

도전과제 2. 시계열 모델 선정 및 Feature Engineering

배경

KPI 예측은 시간에 따라 변화하는 패턴을 학습해야 하는 전형적인 시계열 문제입니다. 하지만 프로젝트 시작 시점에 어떤 모델이 5G RAN 데이터에 적합한지 알 수 없었고, 4종 KPI(PRB, CQI, MCS, Throughput)마다 특성이 달라 단일 모델로는 최적 성능을 내기 어려웠습니다.

또한 시간 정보를 모델이 효과적으로 학습하도록 만드는 것이 핵심 과제였습니다. 단순히 타임스탬프를 숫자로 입력하면 시간의 주기성(예: 하루 24시간, 일주일 7일)을 학습하기 어렵기 때문입니다.

과정

1) 4가지 시계열 모델 비교 분석

각 모델을 4종 KPI에 대해 학습시키고 WAPE(Weighted Absolute Percentage Error) 지표로 비교 평가했습니다. 결과적으로 GRU가 학습 속도와 정확도 면에서 가장 균형 잡힌 성능을 보였습니다.

2) Feature Engineering: sin/cos 변환

  • 시간 정보를 sin/cos 변환으로 주기성 표현
  • 이를 통해 23시와 0시가 가까운 시간임을 모델이 학습 가능
  • 요일, 월 등도 동일하게 변환하여 주기성 반영

3) Cell 단위 학습 전략 (Site-Specific Training)

  • 전체 Cell 데이터를 하나의 모델로 학습하면 일반화 성능은 높지만 개별 Cell 특성 반영 부족
  • Cell별로 독립적인 모델을 학습시켜 각 Cell의 고유한 트래픽 패턴 학습

결과

  • 4종 KPI(PRB, CQI, MCS, Throughput) 모두 90% 이상 예측 정확도 달성 (WAPE 기준)
  • sin/cos 변환 적용으로 시간 주기성 학습 성공, 예측 정확도 7-12%p 향상
  • Cell 단위 학습 전략으로 개별 Cell 특성 반영, 정확도 추가 5-10%p 향상
  • GRU 모델이 가장 균형 잡힌 성능을 보여 최종 모델로 선정

배운 점: Feature Engineering의 중요성을 체감했습니다. 단순히 시간 정보를 숫자로 입력하는 것과 sin/cos 변환으로 주기성을 표현하는 것 사이에 7-12%p의 성능 차이가 발생한다는 것을 확인하며, 도메인 지식과 데이터 이해가 모델 성능에 얼마나 큰 영향을 미치는지 깨달았습니다. 또한 여러 모델을 체계적으로 비교하며, 각 모델의 특성과 적합한 사용 시나리오를 이해할 수 있었습니다.

전체 회고

이 프로젝트는 제한된 리소스 환경에서 대용량 데이터를 다루는 법, 시계열 모델 비교 분석을 통한 최적 모델 선정, Feature Engineering을 통한 성능 향상까지 데이터 사이언스의 전 과정을 경험한 값진 기회였습니다.

특히 삼성전자라는 실제 기업과 함께 산업 문제를 해결하면서, 연구 환경과 실무 환경의 차이를 체감했습니다. RAN 장비에 탑재를 고려한 ONNX 기반 모델 경량화 작업을 통해, 높은 정확도만을 추구하는 것이 아니라 배포 환경의 제약도 함께 고려해야 한다는 것을 배웠습니다.

도전과제 1. 동양인 특화 감정 인식 모델 개발

배경

기존 브라우저 기반 감정 인식 라이브러리인 face-api.js는 서양인 데이터로 학습되어 동양인 얼굴에 대한 인식 정확도가 낮았습니다. 실제 테스트 결과 동양인 감정 분류 정확도가 26-36% 수준에 불과했고, 이는 실제 서비스에 활용하기에는 부족한 수준이었습니다.

프로젝트의 핵심 목표인 "동양인 감정 데이터 수집"을 위해서는 사용자에게 정확한 피드백을 제공할 수 있는 동양인 특화 모델이 필수적이었습니다. 또한 브라우저 환경에서 실시간으로 동작해야 했기 때문에 경량화된 모델이 필요했습니다.

과정

1) 모델 선정: MobileNetV3

  • 브라우저 환경에서 실시간 추론이 가능한 경량 모델 필요
  • MobileNetV3는 ONNX Runtime Web과 호환성이 우수하고, 파라미터 수가 적으면서도 높은 정확도 유지
  • EfficientNet 대비 추론 속도가 빠르고 메모리 효율적

2) 데이터 전처리

  • AI Hub 한국인 감정 인식 데이터셋 활용 (약 10만 장)
  • 얼굴 영역만 160×160 크기로 크롭하여 모델 입력 최적화
  • 7가지 감정 클래스로 레이블링: 행복, 슬픔, 분노, 놀람, 혐오, 공포, 중립

3) Transfer Learning 전략

  • ImageNet 사전학습 가중치에서 시작
  • Staged Fine-tuning: Feature Extractor 레이어는 낮은 학습률(1e-5), Classifier는 높은 학습률(1e-3)

4) ONNX 변환 및 배포

  • PyTorch 모델을 ONNX 포맷으로 변환하여 브라우저에서 실행 가능하도록 최적화
  • ONNX Runtime Web으로 JavaScript API 설계, 실시간 추론 파이프라인 구축

결과

  • face-api.js 대비 Top-1 정확도 32-42%p 향상 (26-36% → 68.65%)
  • 브라우저 환경에서 평균 50ms 이내 실시간 추론 달성
  • 모델 크기 15MB 이하로 경량화하여 빠른 로딩 속도 확보
  • Transfer Learning 활용으로 제한된 데이터(10만 장)로도 실용 수준의 정확도 달성

배운 점: Transfer Learning의 효과를 체감했습니다. 또한 경량 모델(MobileNetV3)을 선택함으로써 정확도와 추론 속도 사이의 트레이드오프를 효과적으로 해결할 수 있었습니다.

도전과제 2. 대용량 파일 업로드 시스템 및 동시성 제어

배경

사용자가 게임 플레이 중 촬영된 영상(평균 30-50MB)을 서버에 업로드해야 했습니다. 초기에는 Spring Boot 서버가 직접 파일을 받아 S3에 업로드하는 방식을 사용했으나, 동시 접속자가 증가하면 서버 메모리 사용량이 급증하고 응답 시간이 3-5초로 늘어나는 문제가 발생했습니다.

또한 게임 완료 시 사용자에게 포인트를 지급하는 시스템에서 동시 요청으로 인해 포인트가 중복 지급되는 동시성 이슈가 발견되었습니다.

과정

1) S3 Pre-signed URL 도입

  • 클라이언트가 서버에 업로드 권한을 요청하면, 서버는 S3 Pre-signed URL을 생성하여 반환
  • 클라이언트가 Pre-signed URL을 통해 S3에 직접 업로드함으로써 서버 부하 제거
  • 서버는 파일 메타데이터(URL, 사용자 ID, 타임스탬프)만 DB에 저장

2) JPA Transaction 기반 동시성 제어

  • 리워드 지급 로직을 @Transactional(isolation = Isolation.SERIALIZABLE)로 감싸 직렬화
  • DB 레벨에서 사용자별 포인트 적립 내역을 UNIQUE 제약 조건으로 중복 방지
  • 낙관적 락(Optimistic Lock)을 통해 버전 충돌 감지 및 재시도 로직 구현

결과

  • S3 Pre-signed URL 도입으로 서버 메모리 사용량 80% 감소
  • 파일 업로드 응답 시간 3-5초 → 300ms 이하로 단축
  • 동시성 제어 적용으로 리워드 중복 지급 버그율 0% 달성
  • 서버 처리 성능 향상으로 동시 접속자 수 10배 증가 가능

배운 점: 클라이언트-서버 간 역할 분담의 중요성을 깨달았습니다. 서버가 모든 작업을 처리하려 하지 않고, S3 Pre-signed URL을 활용해 클라이언트가 직접 파일을 업로드하도록 설계함으로써 서버 부하를 효과적으로 분산했습니다. 또한 동시성 문제를 Transaction Isolation Level과 DB 제약조건으로 해결하며, 실제 서비스에서 발생할 수 있는 예외 상황을 사전에 방지하는 방어적 프로그래밍의 중요성을 체감했습니다.
